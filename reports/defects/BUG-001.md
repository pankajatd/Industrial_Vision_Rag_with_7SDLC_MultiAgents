## 1. Defect Description
In the Streamlit operator cockpit dashboard, the dual-viewport comparison canvas displayed a noticeable vertical misalignment between the Left Viewport (`Raw Sensor Input`) and the Right Viewport (`AI Defect Mask`). The right-hand image was pushed downward by approximately 28 pixels relative to the left image, breaking the horizontal visual baseline.

## 2. Steps to Reproduce
1. Launch the Streamlit application via `streamlit run src/app.py`.
2. Under "Source Input Mode", select "Upload Metal Component Photo".
3. Upload any sample metal image (e.g., `04_cold_rolled_steel_flawless_pass.png`).
4. Inspect the side-by-side camera viewports in the browser.
5. Notice that the top black HUD banner of the right image begins significantly lower than the top edge of the left image.

## 3. Expected vs. Actual Behavior
- **Expected:** Both image containers must align along the exact same horizontal pixel baseline across their top and bottom edges.
- **Actual:** The right image container was offset downwards due to asymmetric header text wrapping.

## 4. Root Cause Analysis
In `src/app.py`, the two column headers had unequal text lengths:
* Left column: `st.markdown("##### 📷 Raw Sensor Input (Live Conveyor View)")` (Rendered cleanly on 1 line).
* Right column: `st.markdown("##### 🔬 AI Defect Mask (Grain-Neutral Subtraction & HUD)")` (Wrapped onto 2 lines on standard 1080p browser viewports).
Because the right-hand header wrapped into two lines, Streamlit pushed the image below it down by the height of an entire text line. Additionally, the bottom caption formatting was asymmetric.

## 5. Developer Resolution (Applied by Software Developer Agent)
- Created a dedicated CSS class `.viewport-header` with `white-space: nowrap;`, fixed padding, and standard font sizing.
- Standardized both header titles to concise, non-wrapping single-line strings:
  - Left: `<div class="viewport-header">📷 Raw Sensor Input (Live Conveyor View)</div>`
  - Right: `<div class="viewport-header">🔬 AI Defect Mask (Flaw Overlay & HUD)</div>`
- Standardized bottom captions across both viewports with identical container widths (`use_container_width=True`).

## 6. QA Retest & Verification Results
- **Visual Baseline Verification:** Inspected both image containers in browser across 100%, 125%, and 150% display scaling. Both containers start at the exact same vertical coordinate ($y = 248\text{px}$).
- **Browser Theme Compatibility:** Verified clear contrast across both Light Mode and Dark Mode.
- **Regression Test:** All automated UI tests verified.
