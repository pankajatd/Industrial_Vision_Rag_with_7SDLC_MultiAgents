## 1. Defect Description
When generating a maintenance work order via `generate_work_order()` in `src/detector.py`, if the `defect_type` parameter was passed with trailing whitespace or inconsistent casing (such as `"CRACK "` or `" Dimensional"`), the RAG query lookup dictionary failed to match the defect, triggering the fallback general safety procedure instead of the specific metallurgical repair SOP.

## 2. Steps to Reproduce
1. Call `detector.generate_work_order(101, "CRACK ", 9.0, "CRITICAL")`.
2. Inspect the returned work order dictionary.
3. Observe that `cited_manuals` returned `["SOP-000-GENERAL.md"]` instead of `["SOP-001-CRACK.md"]`.

## 3. Expected vs. Actual Behavior
- **Expected:** Defect type string must be normalized so that `"CRACK "`, `"crack"`, or `"Crack"` correctly matches the crack repair manual `SOP-001-CRACK.md`.
- **Actual:** Key lookup failed due to exact dictionary string matching.

## 4. Root Cause Analysis
`query_map` in `generate_work_order()` evaluated `defect_type` without `.lower().strip()` sanitization:
```python
search_query = query_map.get(defect_type, "general plant safety maintenance procedure")
```

## 5. Developer Resolution (Applied by Software Developer Agent)
- Added defensive input sanitization in `generate_work_order`:
  ```python
  defect_clean = defect_type.lower().strip()
  search_query = query_map.get(defect_clean, "general plant safety maintenance procedure")
  ```
- Harmonized all downstream work order conditional branches to evaluate against `defect_clean`.
