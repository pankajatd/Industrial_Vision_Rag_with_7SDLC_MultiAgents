## 1. Defect Description
When uploading a single-channel 2D grayscale image (shape `(H, W)`) or a 4-channel transparent PNG (shape `(H, W, 4)`), `load_and_validate_image()` in `src/utils.py` raised an `IndexError` when attempting to access `frame.shape[2]` on 2D arrays, causing the perception pipeline to crash.

## 2. Steps to Reproduce
1. Ingest a 2D grayscale array directly via `load_and_validate_image(np.zeros((512, 512), dtype=np.uint8))`.
2. Notice the `IndexError: tuple index out of range` on dimension checking.

## 3. Expected vs. Actual Behavior
- **Expected:** The normalization engine must accept any valid image array (grayscale 2D, BGR 3D, or RGBA 4D) and reliably output a standard 3-channel RGB `(512, 512, 3)` uint8 tensor.
- **Actual:** Crashed on 2D arrays lacking a third dimension.

## 4. Root Cause Analysis
In `src/utils.py`, the image shape evaluation logic checked `if frame.shape[2] == 4:` before verifying if `len(frame.shape) == 2`. For a 2D matrix, evaluating `shape[2]` triggers an immediate `IndexError`.

## 5. Developer Resolution (Applied by Software Developer Agent)
- Added defensive dimensional guards in `load_and_validate_image`:
  ```python
  if len(frame.shape) == 2:
      frame = cv2.cvtColor(frame, cv2.COLOR_GRAY2RGB)
  elif len(frame.shape) == 3 and frame.shape[2] == 4:
      frame = cv2.cvtColor(frame, cv2.COLOR_RGBA2RGB)
  ```
- Ensured uniform resizing to `target_size=(512, 512)` with `cv2.INTER_AREA` interpolation.

- **Result:** PASSED — 2D grayscale array normalized to `(512, 512, 3)` uint8 RGB.
